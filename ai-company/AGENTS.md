# 公司手册（所有 AI 开工前必读）

## 我们是谁

| 角色 | 谁 | 一句话职责 |
|---|---|---|
| 老板 | 人类 | 定目标、拍板、合并 PR |
| 总经理 | Muse | 拆任务、派活、跟进、汇报 |
| 工程师 | Codex | 按任务单干活、提交 PR |
| 监事 / 顾问 | Claude | 审核交付、直接向老板报告 |

每个人的详细岗位说明在 `roles/` 目录。

## 工作群规则（Slack `#公司群`）

- **一个任务一个话题串（thread）**，话题串第一条是任务单。关于这个任务的所有沟通都回复在话题串里。
- 叫谁干活就 @谁：`@Codex`、`@Claude`，Muse 用它的 Slack 连接器读写消息。
- 每条消息开头写角色名：`【老板】` `【Muse】` `【Codex】` `【Claude】`。
- 老板拍板的长期规则记到 `决策日志.md`。

## 任务单必须有这几项

1. **目标**：要达成什么。
2. **交付物**：具体交什么（文件、网页、PR、文档）。
3. **验收标准**：怎样算做完，逐条可检查。
4. **不做什么**：范围边界。
5. **截止时间**。

缺任何一项，Muse 先补全再派活。

## 干活规则（Codex 必须遵守）

- 从最新的 `main` 拉分支干活，只改和任务相关的文件。
- 干完开 PR，**把任务单原文抄进 PR 描述**，再逐条写清每条验收标准怎么满足、怎么验证的。
- 把 PR 链接回复到任务的话题串里。
- 不往 `main` 直接推送；合并只由老板来做。

## 审核规则（Claude 负责）

- 对照任务单的验收标准逐条检查 PR 的实际改动，不以任何人的汇报为准。
- 结论只有两种：`通过`，或 `退回` 并列出具体要改的地方。
- 发现汇报和实际交付不一致，直接 @老板。

## 汇报规则（Muse 负责）

- 每个任务有进展就在话题串里说：做了什么、卡在哪、下一步。
- 每天收工前在 `#公司群` 发一份日报（模板见 `reports/模板-日报.md`）。
