# 备用方案（不用 Slack 时）

主方案是 Slack，见 [开张清单.md](开张清单.md)。下面两套是之前搭好的备用做法，代码都在仓库里，需要时再用。

## A. Muse 在自己的云电脑上直接调 Codex（GitHub Issues 当任务板）

- 任务 = GitHub Issue（模板：`.github/ISSUE_TEMPLATE/任务单.md`），状态用标签：`待派活` → `进行中` → `待审核` → `待老板批准`。
- Muse 在云电脑上运行 `./scripts/派活.sh <Issue编号>`：自动切分支、调用 Codex、提交 PR、改标签、在 Issue 里汇报；返工时会把 Claude 的退回意见一起交给 Codex。
- `./scripts/看板.sh` 看所有任务状态；`./scripts/初始化.sh` 一次性建好标签。
- 云电脑准备：`gh auth login`，克隆仓库到 `~/ai-company`，确认 `codex` 已登录。

## B. Telegram 工作群

- Telegram 规定机器人之间互相看不到消息，所以由 Muse 云电脑上的中枢程序 `telegram/hub.py` 统一收发。
- 建 3 个机器人（@BotFather → `/newbot`），给 Muse 机器人关闭隐私模式（`/setprivacy` → `Disable`），拉进同一个群。
- 在云电脑上：`cp telegram/.env.example telegram/.env` 填好 3 个 token；`python3 telegram/hub.py ids` 查群 ID 和你的用户 ID 填进去；然后 `nohup python3 telegram/hub.py run >> telegram/data/hub.log 2>&1 &`。
- 群里 `@codex` / `@claude` 会叫对应的 AI 干活；Muse 用 `./scripts/群聊.sh 等` 读 @它的消息，用 `./scripts/群聊.sh 说 "内容"` 发言。AI 之间互相 @ 最多连续接力 6 轮。
